# Pre-registration C0: `noise_ladder=False` полностью отключает ladder

**Date:** 2026-10-11, до запуска (HEAD `af922d2`).
**Статус:** зарегистрирован до прогона. Выполняется до T1.

## 1. Что проверяется и что нет

**Проверяется:** при `Features(noise_ladder=False)` выход `zeroresp.py` побитово совпадает с выходом той же стратегии, где ladder-код не вызывается вообще. Эталоном служит `zeroresp.py` с `noise_ladder=False`.

**Не проверяется:** эквивалентность историческому v5.2. Независимого кода v5.2 без ladder в репозитории нет: все варианты (`variants/A`–`D`, `zeroresp.py`, `zeroresp_v54`–`v56`) содержат ladder, а `ZeroResp v5.2.html` содержит только описание. Поэтому C0 не может утверждать, что `noise_ladder=False` равен v5.2. Этот вывод запрещён, даже если тест пройден.

## 2. Гипотеза

H0 (ожидаем): `noise_ladder=False` не меняет ни одного хода ни в одном матче. Ladder полностью отключён.

H1 (альтернатива, которую проверяем): существует хотя бы один ход, где `noise_ladder=False` даёт иной выбор, чем ожидалось бы без ladder. Тогда флаг не отключает ladder полностью.

## 3. Как проверяется «эталон без ladder»

Эталон формируется **без вызова ladder-кода**, а не через флаг. Для этого в копии `zeroresp.py` (не в боевом файле) все ветки `if self.features.noise_ladder:` заменяются на `if False:`. Копия называется `zeroresp_noladder_ref.py` и создаётся до прогона. Функция `_nl_noise_proven()` и связанные методы не вызываются.

Тогда:
- Test A: `ZeroResp(features=Features(noise_ladder=False))` из `zeroresp.py`.
- Test B: `ZeroResp()` из `zeroresp_noladder_ref.py`.
- Ожидание: A и B побитово совпадают.

Если они расходятся, значит флаг `noise_ladder=False` не отключает некоторый путь ladder. Это и есть результат H1.

## 4. Дизайн

- Пул: `--pack full`, 221 оппонент.
- Сиды: 30, с 42 по 71.
- Шум: iid action flip 10%.
- Длина: 200 ходов.
- Сравнение: **вся история ходов по позициям** для обоих игроков на каждом из `30 × 221 = 6630` матчей. Не SPT, а сырой список `(my_action, opp_action)` на каждом ходе.

## 5. Критерий

- **Эквивалентность подтверждена:** 0 расхождений по позициям во всех 6630 матчах. Тогда флаг отключает ladder полностью, при этом условии.
- **Эквивалентность не подтверждена:** хотя бы одно расхождение. Тогда T1 не запускается, пока не найдена скрытая зависимость от ladder.

Порог «почти 0» не используется. Допустимо только 0 расхождений.

## 6. Что это значит для T1

T1 использует `noise_ladder=False` как контроль «без ladder». Если C0 не подтверждён, контроль v5.2 в T1 невалиден, и T1 переписывается. Если C0 подтверждён, контроль валиден только в смысле «флаг отключает ladder», а не «равен историческому v5.2».

## 7. Предсказание

Ожидаю H0: флаг полностью отключает ladder. Основание: ladder-ветки защищены `self.features.noise_ladder` напрямую (строки 362, 595, 671, 674, 677, 885 в `zeroresp.py`). Риск H1: побочные состояния, которые меняются даже при выключенном ladder (например, `_nl_*` поля, обновляемые вне гейта). Их нужно проверить отдельно при разборе расхождений, если они найдутся.

## 8. История прогонов (добавлено после первого прогона)

- **C0 v1 (не пройден):** 2 расхождения из 6630 (сид 58 FirstByDowning ход 38; сид 71 Calculator ход 112).
- **Причина (установлена):** инструмент, а не ladder. Игроки создавались без явного сида, ZeroResp.__init__ берёт warmth из глобального RNG Axelrod, поэтому порядок создания менял начальное состояние. ladder-счётчики (
l_*) и число RNG-вызовов совпадали.
- **Исправление:** uild(cls, seed, role) сидирует модульный RNG непосредственно перед созданием каждого игрока; детерминированно от (seed, role). Критерий и 0-расхождений не меняются.
- **C0 v2:** повторный полный прогон после исправления — отдельный результат, фиксируется в enchmarks/results/C0_ladder_off_check.json (перезапись).
