# Pre-registration T1 (both-flip): ZeroResp v5.3 при одновременном action- и perception-шуме

**Date:** 2026-10-11, до запуска прогонов (HEAD `af922d2`).
**Статус:** зарегистрирован до реализации канала. Раннер ещё не написан. Все результаты ниже — план.

## 1. Почему отдельный канал

Axelrod применяет шум только к действию: `Match.simultaneous_play` вызывает `random_flip(s1, noise)` и не имеет perception-флипа. Both-flip требует собственной обёртки поверх `Match`.

## 2. Определение both-flip (фиксируется до прогона)

**Обе стороны искажены одинаково.** Для каждого игрока и каждого хода:

- **Action-канал:** намеренное действие `a` переворачивается с вероятностью `p`. Реализованное действие = `flip(a)` с вероятностью `p`, иначе `a`.
- **Perception-канал:** наблюдение соперника `o` (его реализованное действие из прошлого хода) переворачивается с вероятностью `p`, независимо от action-канала. Стратегия получает `flip(o)` с вероятностью `p`, иначе `o`.

**Биты независимы.** Для каждого хода и каждого игрока берутся два независимых бита: один для action, другой для perception. Одна общая `p` на событие не используется.

**Параметр:** `p_action = p_perception = p`, где `p ∈ {0.00, 0.05, 0.10, 0.20}`. Асимметрия (`p_action ≠ p_perception`) в этом протоколе не проверяется; это отдельный тест.

**Что видит стратегия.** Искажённую историю: и собственное решение (через perception собственного действия при расчёте), и наблюдение соперника. Стратегия не знает, какие её ходы были перевёрнуты.

**Что видит оппонент.** Та же схема: его собственный action и perception его собственного наблюдения за ZeroResp. Оба игрока получают искажённую информацию симметрично.

**Истории для анализа.** Сохраняются реализованные действия (после action-флипа) и истинные наблюдения. Метрика SPT считается по реализованным действиям, так же, как в `Match.scores()`.

## 3. Базовая версия и контроли

- **Базовая:** v5.3 (`zeroresp.py`).
- **Контроль 1:** v5.2 (ladder off). Нужен, чтобы отличить «ladder работает» от «ladder мешает» или «ladder спит». Версия v5.2 доступна через `Features(noise_ladder=False)` в `zeroresp.py`; отдельный файл v5.2 есть в `ZeroResp v5.2.html`, но не как импортируемый модуль. Проверить до запуска, что `noise_ladder=False` даёт поведение v5.2 (сравнением с `ZeroResp v5.2.html` или с уже записанным `--no-ladder`).
- **Контроль 2:** v5.5 (`zeroresp_v55.py`). Установленная регрессия при iid 10%: Δ = −0.0517. Нужен, чтобы видеть, сохраняется ли регрессия при both-flip.

## 4. Гипотезы и критерии (фиксируются сейчас)

**H1 (топ-10).** При both-flip 10% v5.3 входит в топ-10: `mean_rank ≤ 10` по 30 сидам.

**H2 (ladder работает или спит).** Δ = SPT(v5.3) − SPT(v5.2) на тех же сидах:
- «Ladder спит»: `|Δ| < 0.005` и `p > 0.05`.
- «Ladder работает»: `Δ ≥ +0.02` и `p < 0.05`.
- «Ladder мешает»: `Δ ≤ −0.02` и `p < 0.05`.
- Всё между этими порогами — неопределённость, а не вывод.

**H3 (контроль v5.5).** Δ = SPT(v5.5) − SPT(v5.3) при both-flip 10%. Регрессия подтверждается, если `Δ ≤ −0.03` и `p < 0.05`. Отсутствие регрессии, если `|Δ| < 0.005` и `p > 0.05`.

## 5. Design

- Пул: `--pack full`, 221 оппонент (+ ZeroResp = 222).
- Сиды: 30, с 42 по 71.
- Длина: 200 ходов.
- Уровни `p`: 0, 0.05, 0.10, 0.20.
- Пары: одинаковые сиды и оппоненты для всех версий.

## 6. Analysis

- Парные Δ по сидам: Wilcoxon signed-rank, bootstrap 95% CI.
- Holm-Bonferroni по уровням `p` внутри каждого сравнения.
- Для H2 и H3 отдельно по сидам (как в `seed_breakdown.py`): сколько оппонентов с идентичной историей против расходящейся.

## 7. Prediction

- H1: выполняется при 5% и вероятно при 10%.
- H2: по гипотезе «ladder спит» при both-flip, поскольку perception-флип ломает детектор необъяснённых D. Предсказание: `|Δ(v5.3 − v5.2)| < 0.005`. Если оно не сбудется, это будет зафиксировано как отрицательный результат.
- H3: регрессия v5.5 сохранится, но её величина может измениться.

## 8. Ограничения

- Реализованные результаты iid-шума из `versions_*.md` и `paired_*.json` не переносятся на both-flip.
- Одна обёртка, одна интерпретация both-flip. Другие определения (например, только perception на одной стороне) дают другие результаты и требуют своего pre-reg.
